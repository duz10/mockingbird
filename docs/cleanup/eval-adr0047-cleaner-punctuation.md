## Diagnosis

**Per-failure classification.** Both failures are mild edits that don't
match the over-consolidation regression class this eval was chartered
to catch.

| Fixture | Edit | Class | Over-consolidation? |
|---|---|---|---|
| `14_question_then_answer` | `flips true` -> `flips to 'true'` | Inserted preposition (1 word) | No — content fully preserved, grammar tweaked. Technical violation of the prompt's "do not add words" rule, but semantically null. |
| `18_meta_request` | `sort of like` -> `kind of like` | Hedge paraphrase | No — hedge preserved, same register. Technical violation of "do not paraphrase" but the hedge survives semantically. |

Neither failure drops a preamble, an aside, a parenthetical, or any
structural content. The Wave 1.1 fix attacked the failure mode where
the global `SYSTEM_HEADER` ("Be concise...") instructed the 3B model
to discard content; that class is **absent** from the post-Wave-1
run. The remaining 2 failures are residual 3B model-size artifacts —
short, locally-scoped edits at the phrase level — and would
likely shrink further on the 7B model.

**Headline finding.** The per-pass system header (Wave 1.1) is
empirically validated as the load-bearing fix for the over-consolidation
class. The eval rig is now permanently in place to detect a regression
should a future prompt-body or model-default change re-introduce the
failure class.

**Decision: SEAL Wave 3.** 18/20 hits the ADR §Wave 3 expected floor;
the 2 misses are pre-existing 3B-model phrase-edit noise, not new
regression classes. Per the kickoff stop-condition ("eval surfaces a
true regression that's not pre-existing -> STOP"), no stop applies.

**LLM judge intentionally skipped.** ADR §Wave 3.2 proposed an
optional LLM judge asserting "the word `concise` does not appear in
any assembled `cleaner_punctuation` prompt". That invariant is already
covered statically by the unit tests in `meetings/llm_pass.rs`
(commit `d6974a2`): `cleaner_punctuation_prompt_does_not_include_concise`,
`header_for_prompt_maps_each_variant`, `summary_prompt_keeps_concise_header`,
`action_items_prompt_keeps_concise_header`. A judge adds verification
cost without adding signal beyond what the unit tests give. The
fixture-based eval above IS the more valuable artifact because it
tests end-to-end behaviour, not just prompt assembly.
